# AI Repository Foundation Ruleset

Status: AUTHORITATIVE BASELINE
Ruleset version: 1.21.0

## Protected floor

Current platform/user authority and repository sources govern the work. Classify data and destinations; preserve secrets, privacy, licenses, authorization, durable identity, and truthful evidence. A concrete task permits proportionate ordinary operations inside its envelope. Escalate only a real unresolved boundary. Native scoped instruction discovery remains mandatory. Foundation validation proves only FOUNDATION_INTEGRITY; required PROJECT_SEMANTIC and RUNTIME_EMPIRICAL checks remain project-owned.

REQUIRED rules are a protected minimum. DEFAULT workflow may be intentionally overridden; PROJECT_SELECTABLE choices belong to the target. Preserve compatible stricter governance and report conflicts. Chat history, cached analysis, fingerprints, and identifiers are never authority.

## Working default

Read affected project sources and only policies relevant to the task. For routine work: inspect, change, validate, report. Use one implementation owner and the smallest sufficient checks plus required gates. Prefer deterministic local processing. Extra agents and reviews require a distinct useful question. Required independent review is preserved. A timer, green result, or completed review does not itself justify another model call.

Inspect logs locally and provide bounded findings. Separate diagnosis/integration from qualification/release; deduplicate checks at identical relevant bindings. Installation/upgrade and material workflow-rule changes REQUIRE an assessment of actual test, log, review, and model-call overhead, including bounded reasons for stricter exceptions. Unresolved areas remain pending; a green integrity check alone does not complete efficiency integration.

Follow `PROCESSING_EFFICIENCY_POLICY.md` for session-local rule reuse, review/agent bounds, shared wave budgets, waiting, and efficiency recommendations. The core `runtime/processing_efficiency.py` is a dependency-free reference; another language/client implementation is equally valid. Native discovery and current source/dependency checks precede reuse of actually available analysis. Optional persistent caching retains `RULE_CONTEXT_CACHE_POLICY.md` and does not fabricate missing analysis.

## Read only the relevant boundary

- Ordinary workflow/validation: `WORKING_RULES.md`, `VALIDATION_POLICY.md`.
- Data/security/licensing: `DATA_PRIVACY_AND_CONFIDENTIALITY.md`, `SECURITY_AND_SAFE_OPERATIONS.md`, `THIRD_PARTY_AND_LICENSING.md`.
- Documentation/evidence/dependencies: `DOCUMENTATION_POLICY.md`, `SOURCE_AND_EVIDENCE_POLICY.md`, `DEPENDENCY_POLICY.md`.
- Installation, local overrides, upgrade: `SEMANTIC_INTEGRATION_POLICY.md`, `UPGRADE_APPLICABILITY_POLICY.md`, `feature_catalog.json`.
- Identity/registration changes: `PERSISTENT_IDENTITY_POLICY.md`, `ARTIFACT_REGISTRATION_POLICY.md`, `CENTRAL_ARTIFACT_REGISTRY_POLICY.md`.
- Persistent cache use: `RULE_CONTEXT_CACHE_POLICY.md`.
- Concrete model selection: `MODEL_ROUTING_POLICY.md`.
- Executable AI orchestration, adapters, provisioning, or session rotation: `AI_WORK_ORCHESTRATION_POLICY.md`.
- CI outages/supersession: `REPOSITORY_CONTINUITY_POLICY.md`.

`repo_map.yaml` is a discovery index, not a bulk-reading list. `FOUNDATION_REFERENCE.md` retains detailed integration and capability boundaries; consult its relevant section when needed. Schemas constrain the corresponding selected operation, not every routine edit. Optional capabilities remain opt-in and confer no authority. Do not claim a model switch, new session, runtime proof, or completed check without supporting execution evidence.
