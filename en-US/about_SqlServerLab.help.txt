TOPIC
    about_SqlServerLab

SYNOPSIS
    Overview, naming model, and common workflows for the SqlServerLab module.

LONG DESCRIPTION
    SqlServerLab creates and manages isolated SQL Server test environments with
    Docker or Podman. The module supports direct ad-hoc calls and declarative
    JSON manifests.

    All public commands use the PowerShell Verb-SingularNoun pattern. The
    module name is SqlServerLab. All public nouns start with SqlServerLab and
    identify resources owned by this module.

COMMAND DISCOVERY
    List all exported commands and their module ownership:

        Get-Command -Module SqlServerLab | Sort-Object Name

    List names and short descriptions:

        Get-Command -Module SqlServerLab | Sort-Object Name |
            ForEach-Object {
                [pscustomobject]@{
                    Name     = $_.Name
                    Synopsis = (Get-Help $_.Name).Synopsis
                }
            } | Format-Table -AutoSize -Wrap

    Display full, parameter, or example help:

        Get-Help New-SqlServerLab -Full
        Get-Help Test-SqlServerLabManifest -Parameter Path
        Get-Help Restore-SqlServerLabDatabase -Examples

    Use a module-qualified name if another command has the same name:

        SqlServerLab\New-SqlServerLabDatabase

COMMANDS
    Entry point and provisioning

    Invoke-SqlServerLab
        Opens the interactive menu or runs one menu action directly.

    New-SqlServerLabBatch
        Validates, expands, persists, and queues one or more provider-neutral items.

    Get-SqlServerLabBatch
        Returns persistent batch plans, dependencies, progress, and cleanup scope.

    Get-SqlServerLabQueue
        Returns workers, locks, blocked items, and pending user gates.

    Invoke-SqlServerLabScheduler
        Processes the persistent batch queue with bounded workers until idle.

    Get-SqlServerLabOperation
        Returns persistent child operations, steps, receipts, and events.

    Confirm-SqlServerLabOperationUserAction
        Verifies selected user gates individually and resumes only successful items.

    Move-SqlServerLabOperation
        Reorders a waiting operation within its priority.

    Set-SqlServerLabOperationPriority
        Sets an individual High, Normal, or Low operation priority.

    Suspend-SqlServerLabOperation
        Pauses a waiting operation.

    Resume-SqlServerLabOperation
        Releases a paused operation when dependencies allow it.

    Stop-SqlServerLabOperation
        Stops an operation at a safe boundary and can clean only its owned scope.

    Stop-SqlServerLabBatch
        Stops unfinished items or explicitly rolls back all batch-owned resources.

    Get-SqlServerLabWorkflow
        Returns the consolidated workflow view for local labs, Windows
        baselines, SQL prepared images, and acceptance environments.

    Get-SqlServerLabCatalog
        Builds a consolidated, secret-free runtime catalog of current labs,
        templates, and artifacts and stores it as JSON.

    Get-SqlServerLabCleanupAudit
        Inventories known lab data and runtime resources read-only and reports
        residuals or unavailable providers without removing anything.

    Get-SqlServerLabConnectionCenter
        Returns the password-free SQL endpoint catalog used by SSMS and CMS.

    Sync-SqlServerLabConnectionCenter
        Atomically refreshes the local connection-center catalog.

    Export-SqlServerLabSsmsRegistration
        Creates a password-free SSMS Registered Servers import file.

    Export-SqlServerLabCmsSyncScript
        Creates an idempotent synchronization script for an existing CMS.

    Initialize-SqlServerLabCms
        Creates an explicitly requested compact persistent Docker or Podman CMS.

    Sync-SqlServerLabCms
        Synchronizes a managed local CMS with the current endpoint catalog.

    Get-SqlServerLabReconcilePlan
        Returns a read-only lifecycle plan or a resolver-bound external-runtime
        refresh plan for an existing run.

    Invoke-SqlServerLabReconcileAction
        Executes an unambiguous START/STOP plan or an additive, validated SQL
        Server 2022 Docker/Podman external-runtime refresh.

    Invoke-SqlServerLabWorkflowAction
        Runs one explicit non-interactive Hyper-V workflow action for the
        local browser user interface.

    New-SqlServerLab
        Creates a lab environment from parameters or a manifest.

    Manifest

    New-SqlServerLabManifest
        Creates and saves a schema-validated JSON manifest.

    Test-SqlServerLabManifest
        Validates a manifest file or object without provisioning.

    Status and lifecycle

    Get-SqlServerLab
        Shows saved state and, when available, live runtime status.

    Start-SqlServerLab
        Starts a stopped lab environment.

    Stop-SqlServerLab
        Stops a running environment without removing it.

    Restart-SqlServerLab
        Stops and starts a lab environment in one operation.

    Remove-SqlServerLab
        Removes one run by executing its cleanup plan.

    Clear-SqlServerLab
        Cleans multiple runs and orphaned lab containers.

    SQL operations

    New-SqlServerLabDatabase
        Creates a database with optional file and database settings.

    Restore-SqlServerLabDatabase
        Restores a database from a local or remote .bak file.

    Invoke-SqlServerLabScript
        Executes a T-SQL script with GO batch support.

    Get-SqlServerLabGeneratedSqlAccess
        Returns runtime SQL access for an automatically generated SQL Server SA
        account, including the connection string.

    New-SqlServerLabAutomatedTestEnvironment
        Creates one or more Linux SQL test environments with separate random
        passwords and refreshes the test environment contract.

    Export-SqlServerLabTestEnvironment
        Writes TestUmgebung.env, TestUmgebung.json, TestUmgebung.schema.json,
        TestUmgebung.prompt.md, and TestUmgebung.md to the
        configured Lab_Data export directory.

    Clear-SqlServerLabAutomatedTestEnvironment
        Removes all automated test environments as one protected group and
        deletes the corresponding TestUmgebung export.

    Validation

    Test-SqlServerLabPrerequisite
        Tests provider, RAM, storage, ports, and path safety without mutation.

    Project adapters

    Test-SqlServerLabAdapter
        Validates a project adapter against schema and path boundaries, and
        optionally against a concrete run instance, without any mutation.

    Install-SqlServerLabAdapter
        Applies a validated adapter entrypoint (install, update, validate,
        cleanup) to a running instance; no lifecycle side effects.

    Install-SqlServerLab7Zip
        Optionally installs 7-Zip through winget after explicit confirmation for
        catalogued .7z backups with a .bak payload.

NAMING AND OWNERSHIP
    PowerShell associates each exported command with SqlServerLab through the
    Source and ModuleName properties:

        Get-Command New-SqlServerLabDatabase | Select-Object Name, ModuleName, Source

    All public nouns start with SqlServerLab. The former generic Lab-prefixed
    names were replaced before version 1.0 without compatibility aliases or a
    deprecation period.

    Import-Module -Prefix can add a session-local prefix if name conflicts must
    be avoided. It does not modify the module:

        Import-Module .\SqlServerLab.psd1 -Prefix Company
        Get-Command -Module SqlServerLab

TYPICAL WORKFLOW
    Import the module and test resources:

        Import-Module .\SqlServerLab.psd1 -Force
        Test-SqlServerLabPrerequisite -Provider docker

    Create, validate, and provision a manifest:

        New-SqlServerLabManifest -Path .\my-lab.json
        Test-SqlServerLabManifest -Path .\my-lab.json
        $lab = New-SqlServerLab -Manifest .\my-lab.json

    Query status and remove the environment:

        Get-SqlServerLab -RunId $lab.RunId -Detailed
        Remove-SqlServerLab -RunId $lab.RunId
